# 改善タスク運用

「改善管理」では記事単位の提案を、未対応、対応中、完了、保留、対象外として管理します。記事修正日は利用者の表示タイムゾーン上の日付を `DATE` のまま保存し、Search Consoleの実績日（America/Los_Angeles）と混同しません。

同じプロパティ、正規化URL、種別、検索語、提案内容から安定ハッシュを作り、再分析による重複を防ぎます。既存タスクの状態、メモ、履歴は維持され、完了タスクが自動で再開されることはありません。

比較は修正日の前28日と後28日（修正日を除外）です。CTRは合計から再計算し、平均掲載順位は表示回数で加重します。これは修正前後の変化であり、因果関係を示すものではありません。

## 状態と権限

| 状態 | 用途 |
|---|---|
| 未対応 | まだ着手していない候補 |
| 対応中 | 作業を開始した候補 |
| 完了 | 修正が完了した候補 |
| 保留 | 判断・素材・時期を待つ候補 |
| 対象外 | 対応しないと判断した候補 |

スーパーユーザーは作成・更新でき、viewerは読み取り専用です。メニュー表示だけでなくルーターとPOST処理でも403にします。

## 履歴と効果測定

作成、更新、状態変更、担当、メモ、記事修正日を追記専用履歴へUTC保存します。記事修正日を設定すると、修正日を除いた前後28日のクリック、表示、CTR、平均掲載順位を比較します。後期間が28日未満なら暫定値と残り日数を表示します。
