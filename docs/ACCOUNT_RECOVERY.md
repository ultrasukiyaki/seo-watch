# アカウント回復・認証運用

## メール送信設定

`config/local.php.example`の`mail`セクションを`config/local.php`へ追加します。初期値は`enabled => false`です。送信確認後だけ`true`へ変更してください。外部SMTPライブラリは使わずPHPの`mail()`でUTF-8プレーンテキストを送ります。公開ベースURLはHTTPSの`app.base_url`から生成し、HTTP Hostヘッダーは使いません。

`config/local.php`は秘密情報を含むため、Gitへ追加しないでください。

## メールアドレス登録と確認

ログイン後の「アカウント」で現在のパスワードと新しいメールアドレスを入力します。確認URLを開くまでは現在のアドレスを変更しません。既存環境のユーザーはメール未登録でも引き続きログインできます。

## パスワード再設定

ログイン画面の「パスワードを忘れた方」から、ユーザー名またはメールアドレスを入力します。アカウントの有無にかかわらず同じ案内を表示します。URLは標準30分、一度だけ利用でき、再発行時に以前のURLは無効になります。完了後の自動ログインは行いません。

パスワードは12〜128バイトで、ユーザー名・メールアドレス・現在のパスワードと完全一致する値は利用できません。前後の空白は削除しません。

## 閲覧ユーザー招待

スーパーユーザーはユーザー管理からメール招待または初期パスワード方式を選択できます。招待URLは24時間有効です。受け入れ時にメール確認済み・activeとなります。メール送信が無効な場合、メール招待は選択できません。

## 管理者による手動再設定URL

ユーザー管理でスーパーユーザー自身の現在のパスワードを再入力して発行します。URLは一度だけ画面に表示され、ログや監査ログには保存されません。安全な別経路で対象者へ渡してください。

## CLI緊急リセット

メールが使えない場合はWeb公開外の対話端末で実行します。

```bash
php bin/reset-password.php --user=admin
php bin/reset-password.php --email=admin@example.com
```

パスワードは引数に指定しません。TTYでない標準入力では安全のため停止します。POSIX環境では入力を非表示にします。

## セッション無効化

パスワード再設定、アカウント無効化、管理者の無効化操作は`session_version`を増加し、既存セッションを無効化します。本人による通常変更では現在のセッションIDだけを再生成して継続し、他端末を無効化します。

## 監査ログと保持期間

認証イベントはDBへ保存し、メール・パスワード・生トークン・完全URL・セッションIDは保存しません。スーパーユーザーだけが閲覧できます。標準保持期間は180日です。

```bash
php bin/purge-auth-data.php
```

このコマンドは期限切れトークン、古いレート制限、180日を超えた監査ログを削除します。

## Testing環境とメールが届かない場合

Google OAuthアプリがTesting状態の場合、OAuth更新トークンが短期間で失効することがありますが、認証メールとは別の仕組みです。メールが届かない場合は`mail.enabled`、Fromアドレス、PHPの`mail()`可否、迷惑メールフォルダ、DNSのSPF/DKIM設定を確認してください。任意宛先へのテスト送信はできず、確認済みスーパーユーザーアドレスだけが対象です。

## 漏えいが疑われる場合

対象ユーザーのパスワードを変更し、全セッションを無効化してください。必要ならCLIでスーパーユーザーを回復し、OAuthクライアントシークレット、DB認証情報、アプリ暗号鍵も影響範囲に応じてローテーションします。
