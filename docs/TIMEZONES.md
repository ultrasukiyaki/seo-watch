# タイムゾーン

SEO Watchは、瞬間を表す日時をMySQLへUTCの`Y-m-d H:i:s`形式で保存し、画面・メール・CLIでのみ管理者が選んだ表示タイムゾーンへ変換します。タイムゾーン変更で既存データは書き換わりません。

## 設定

スーパーユーザーで「設定」から、`Asia/Tokyo`などのIANAタイムゾーンを選択します。IANA識別子は固定オフセットと異なり、Europe/LondonやAmerica/Los_Angelesの夏時間（DST）も正しく扱えます。既存環境で未設定の場合は、従来の有効なアプリ設定、PHP標準タイムゾーン、UTCの順で表示用にフォールバックし、確認を促します。

PHP標準タイムゾーンは内部処理の既定値であり、アプリ表示タイムゾーンとは別です。v0.9.0では内部PHP処理とMySQL接続セッション（`SET time_zone = '+00:00'`）をUTCへ固定します。

## Search Consoleの日付

Search Consoleの`startDate`、`endDate`、dateディメンションは`America/Los_Angeles`基準のDATEです。UTC日時や表示タイムゾーンへ変換しません。CronとWebの取得対象日もPTで計算するため、JST表示によって翌日へずれることはありません。

## ログとDST

生ログの瞬間は`2026-07-23T08:42:10Z`のようなISO 8601 UTCを使用します。利用者向け表示は設定タイムゾーンへ変換します。DSTの切替日には現地時刻が飛ぶ、または重複しますが、保存済みUTCの瞬間は変化しません。

## アップデート後の確認

1. スーパーユーザーで「設定」を開き、表示タイムゾーンを保存します。
2. `php bin/doctor.php`を実行し、DBセッションが`+00:00`であることを確認します。
3. 同期履歴と認証監査ログの表示時刻、Search Console基準日（PT）を確認します。

表示が想定外の場合は、PHPでIANAタイムゾーンが利用可能か、設定値が有効か、DB接続ユーザーにセッションタイムゾーン設定が許可されているかを診断結果で確認してください。既存日時へ手動で時差を加算しないでください。

## v0.10系で追加された日付

- 改善履歴、同期履歴、マイグレーション履歴はUTCの `DATETIME` で保存し、表示時だけ設定IANAタイムゾーンへ変換します。
- 記事修正日は利用者が認識する暦日の `DATE` であり、UTC時刻へ変換しません。
- 修正前後比較のSearch Console実績日はAmerica/Los_Angeles基準の `DATE` のまま扱い、JST等へ変換して日付をずらしません。
- 既定比較は修正日の前28日と翌日から28日で、修正日当日は除外します。
